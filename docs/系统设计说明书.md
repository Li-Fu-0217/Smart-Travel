# 智慧旅游智能助手系统 · 系统设计说明书

## 1. 系统概述

本系统是面向旅游场景的全栈平台，围绕「一家人出游」的场景，把行程、待办、预约、拼团、求助、旅游记录、攻略知识、偏好提炼与智能助手串联成闭环。核心亮点是**智能助手**：用 11 个工具承接「查待办 → 提醒同行人 → 查可约时段 → 用户确认 → 下单 → 通知」的完整链路，且有「待确认闸门」防止助手未经用户同意就写库。

## 2. 总体架构

```
Vue 3 前端（管理后台 /admin + 用户前台 /user，角色互斥）
        │  HTTP /api（JWT Bearer）
FastAPI 后端（api → service → model，权限闸门在 service 层）
        ├── MySQL 8（22 张表，system.sql 唯一权威 schema）
        ├── 智能助手 app/agent/（LangGraph ReAct + 规则编排双模式）
        └── ChromaDB（攻略库向量，本地嵌入，无外部 Key）
```

- **前后端分离**：前端 Vite 开发服务器把 `/api`、`/uploads` 代理到后端 8000。
- **两套端**：同一 Vue 工程承载两个独立界面，通过路由守卫 + `data-scope` 区分，ADMIN/USER 互斥。
- **六套主题**：3 色相（sunset/ocean/forest）× 亮/暗，通过 `data-theme` + CSS 设计 token 实现，Element Plus 主色与中性变量映射到 token。

## 3. 分层设计（后端）

| 层 | 目录 | 职责 |
|---|---|---|
| api | `app/api/` | 薄路由：参数校验、鉴权依赖、返回 `Result`/`PageResult`。登录级与 `admin_router` 分开 |
| service | `app/services/` | 业务逻辑 + **权限闸门**（`assert_family_access` 在此层，数据隔离靠它） |
| model | `app/models/` | 22 张表 SQLModel 映射，时间字段 `default_factory=datetime.now` |
| schema | `app/schemas/` | 出入参，出参继承 `CamelModel`（snake_case → camelCase 自动转） |
| common | `app/common/` | `Result`/`PageResult`、`BusinessException`、`constants.py` 词表（§5.8 单一权威） |
| core | `app/core/` | 配置、JWT/安全、依赖注入（`get_db`/`get_current_user`/`require_admin`） |
| agent | `app/agent/` | 智能体独立目录，见 §6 |

约定：`source` 字段区分数据来源（manual/agent/system）；助手办的事与人工办的事落在同一张表、同一套字段、同一套权限校验下，只在 `source` 上留 `agent` 标记。

## 4. 功能设计

### 4.1 业务域

- **认证**：图形验证码 + JWT 登录，USER 登录 `GET /api/menus` 返回空数组（不 403）。
- **旅行者/家庭**：旅行者档案 CRUD + 家庭绑定（`(user_id, traveler_id)` 唯一）；所有业务域经 `assert_family_access` 做归属校验。
- **行程/待办**：行程 CRUD + `GET /trips/today`（今日/逾期/未来两天/预约视图）；待办打卡幂等、撤销。
- **预约**：可预约项目 + 时段生成 + 下单/取消/改约。防超卖两层：`slot_lock` 唯一约束（下单捕获 `IntegrityError`）+ `version` 乐观锁（改约）。
- **模板/偏好**：行程发布为模板、模板复制（`use_count` 原子自增、单事务）；偏好提炼（关键词 → 9 个固定标签双重过滤）。
- **拼团/求助/记录**：报名 upsert（防超卖 + 满员）、SOS 工单（通知家人/管理员）、旅游记录数据隔离。
- **攻略库 RAG**：上传解析（txt/md/pdf）→ 段优先切片（280/40）→ 本地 Chroma 向量化 + 中文关键词 n-gram 混合检索；嵌入模型不可用时降级为纯关键词，不报错。
- **通知**：站内消息收件箱（列表/未读/已读幂等/全部已读）。

### 4.2 前端

- **管理后台 14 页**：数据概览（8 KPI + 4 图表）、旅行者/行程/模板/预约/拼团/求助/攻略/记录/用户/日志/菜单、助手工具说明书、助手日志审计。
- **用户前台 11 页**：关怀看板、今日行程、行程规划、模板广场、预约、拼团、记录、消息、智能助手聊天、档案详情等。
- **数据概览**：8 张 KPI 卡片 + 4 图表（预约状态饼图 / 项目类型柱状 / 近 7 日折线（后端补零）/ 助手工具调用分布），ECharts 渲染、文字颜色跟随主题。

### 4.3 智能助手（§6 核心）

- **编排**：LangGraph `create_agent`（ReAct + `MemorySaver` 检查点，`recursion_limit=12`）；LangChain 仅作模型/工具配套。
- **双模式**：有 `LLM_API_KEY` 且 `AGENT_DEMO_MODE=false` → 模型编排；否则 → 规则编排（关键词意图分类 + 组合链路，仍真实写库）；模型抛异常 → 降级规则编排 + 友好提示。
- **11 个工具**：查询档案/行程待办/可约时段、预约下单、通知同行人、求助告警、攻略检索、行程推荐、写旅游记录、偏好提炼、复制模板。工具是薄壳（调 service），统一经 `execute_tool` 埋点（`agent_tool_call_log`）。
- **中间件**：`TravelAgentMiddleware`（写库二次校验——`book_item` 必须有待确认上下文；每轮用量统计；`traveler_id` 兜底补齐）。
- **三层记忆**：身份注入（`[当前旅行者ID=N]` 拼进消息前缀）+ 短时检查点（`thread_id=u{uid}:{sid}` 隔离）+ 长期 `agent_conversation` 落库（`pending_book` 角色不展示）。
- **结构化输出**：行程推荐仅当轨迹含 `recommend_itinerary`/`copy_trip_template` 时按需抽取 `ItineraryCard`（`with_structured_output`），失败回退纯文本。

## 5. 数据库设计

22 张表：系统 5 + 业务 17，schema 以 `sql/system.sql` 为准（**禁用 `create_all`**）。

**系统表**：`sys_user`、`sys_role`、`sys_menu`、`sys_login_log`、`sys_operation_log`。

**业务表**：
- 档案/绑定：`traveler_profile`、`family_member`
- 行程：`trip_plan`、`trip_todo`、`trip_template`、`trip_template_item`
- 预约：`booking_catalog`、`booking_order`
- 拼团：`group_tour`、`group_tour_signup`
- 求助/记录：`travel_alert`、`travel_record`
- 攻略：`guide_document`、`guide_chunk`
- 通知：`notify_inbox`
- 智能体：`agent_conversation`、`agent_tool_call_log`

**关键约束**：
- `uk_family_traveler`（`family_member.user_id + traveler_id`）防重复绑定；
- `uk_booking_slot_lock`（`booking_order.slot_lock`）防超卖，取消/完成置 NULL 释放；
- `uk_tour_traveler`（`group_tour_signup.tour_id + traveler_id`）防重复报名，报名用 upsert；
- 时间字段 `NOT NULL DEFAULT CURRENT_TIMESTAMP`，模型侧 `default_factory` 匹配；
- 全局枚举取值集中在 `common/constants.py`（§5.8），禁止各处自创。

## 6. 智能体设计

详见施工规范 §6。要点：

- **技术分工**：LangGraph 承载状态图/检查点/步数上限；LangChain 提供 `ChatOpenAI`/`StructuredTool`/消息类型/`create_agent`。
- **工具三条铁律**：① 薄壳，业务在 service；② 统一 `execute_tool` 埋点、异常不穿透；③ 返回值经 `observation_format.py` 转中文（禁止透传 JSON）。
- **待确认机制**：`query_available_booking` 后写入待确认上下文（`agent_conversation.role='pending_book'` + 进程内缓存双写）；`book_item` 无该上下文时被中间件拦下不落库。
- **过程可视化**：`_extract_steps` 只从最后一条 `HumanMessage` 之后解析「思考 → 行动 → 观察」。
- **记忆去重**：先查检查点是否有状态，有则只追加本轮消息，避免短时/长期双写堆叠。
- **审计**：`agent_tool_call_log` 记录每次工具调用的入参/返回/耗时/成败，`response_data` 截断 8000 字符；管理端「助手日志」可按工具名/会话筛选。
