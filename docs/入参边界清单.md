## 三、硬条款落点说明

1. **接口层校验**：以上所有 query/body 非法值都在 API 层（FastAPI 参数校验 / Pydantic schema 校验器）或 service 入口（白名单 → BusinessException 400）拦截，不把未校验值透传进业务。
2. **枚举白名单**：status / itemType / type / dayRange / useRange / role / doc_type / alert_type / source / category / item_type 全部白名单。
3. **日期/数字 try-parse**：visitedDate（date）、rating/days/travelerId/tourId（int）、slot（strptime）→ 失败 400 非 500。
4. **范围端点与标签一致**：useRange=1-5 排除 0、dayRange=1-2 排除 0 天（4.6 已修）。
5. **分页上界 + 排序白名单**：size≤100、current≥1、days≤30；本项目 order_by 全为固定列，无排序字段入参。
6. **错误码位置一致**：业务 400 → HTTP 200 + body code；401/403/404 → HTTP 状态。

> 反向验证口径：删掉任一 `@field_validator` 或 service 白名单 raise，`test_validation.py` / `test_boundary.py` 中对应断言即变红。
